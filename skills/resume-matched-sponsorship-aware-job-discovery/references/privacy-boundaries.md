# Privacy and access boundaries

Treat candidate identities, resumes, immigration details, contact information, job-search history, browsing state, and application outcomes as private runtime data.

- Keep private files outside the repository or under an ignored local directory.
- Do not paste private profile contents into public artifacts, commits, issues, logs, or screenshots.
- Do not request passwords, cookies, tokens, Authorization headers, or complete authenticated requests.
- Use an existing signed-in browser session only for visible, read-only navigation authorized by the user.
- Stop at CAPTCHAs, security checkpoints, authentication barriers, rate limits, and site access controls.
- Do not submit, save, withdraw, or alter an application.
- Use fictional data in tests, examples, and documentation.
- Run the repository privacy scanner before publishing or sharing a fork.
